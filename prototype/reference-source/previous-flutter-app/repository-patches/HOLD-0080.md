# Required patch before running the repository denial matrix

The upstream `.github/workflows/denial-matrix.yml` currently builds its migration manifest from every `supabase/migrations/*.sql`. That conflicts with the owner instruction to keep migration 0080 pending.

In **Apply committed migrations**, replace the unfiltered manifest creation with:

```bash
held='supabase/migrations/0080_least_privilege_classified_anon_revoke.sql'
test -f "$held" || {
  echo "::error::The held migration is missing; refusing an ambiguous replay."
  exit 1
}
mapfile -t files < <(find supabase/migrations -maxdepth 1 -name '*.sql' -print | LC_ALL=C sort)
filtered=()
for f in "${files[@]}"; do
  if [ "$f" = "$held" ]; then
    echo "HELD: $f was not applied."
    continue
  fi
  filtered+=("$f")
done
files=("${filtered[@]}")
printf '%s\n' "${files[@]}" | grep -q '0081_' || {
  echo "::error::Post-hold migrations are absent; review dependencies before replay."
  exit 1
}
```

The existing **Verify migration order (independent replay)** step invokes `supabase/tests/verify-migration-order.sh`, which must be inspected and given the same exact-file exclusion before that step is enabled. Until then, disable that independent replay step rather than allowing it to apply 0080 through a second path. A skip is a coverage limitation, not a successful test.

Keep the existing disposable-database requirement and `CI_ISOLATED_DB=true` guard. Never point this replay at production. Applying 0081 and later while 0080 is held may itself have dependencies; a failed isolated replay must remain failed until the owner reviews the migration sequence. Do not rename, edit, or silently apply 0080 to make the suite pass.
