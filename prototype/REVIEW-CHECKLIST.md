# Review checklist — checklist for approval

This checklist records design approval, not production-release approval. Each section is present in the current preview.

## Review journeys

- [ ] View every core role and confirm its home/navigation.
- [ ] Switch between the predefined administrator and teacher roles on the multi-role sample account.
- [ ] Change branch/session and review the resulting records.
- [ ] Student: open a course, use the lesson stages, answer the quiz, submit homework and inspect progress.
- [ ] Teacher: view only assigned students, mark sample attendance and grade submitted homework.
- [ ] Editor → administrator → student: save, submit, approve, publish and see the published lesson.
- [ ] Accountant: create a sample receipt and preview/print it.
- [ ] Receptionist: create an enquiry and update its stage.
- [ ] Librarian: issue an available book, verify it cannot be issued twice, then return it.
- [ ] Parent: verify linked children and restricted finance tabs.
- [ ] Inspect notices, templates, CMS, reports and the sample audit log.
- [ ] Check mobile spacing, menu, dialog, writing canvas and printing layouts.
- [ ] Confirm the optional modules remain deferred.

## Representations requiring real implementation later

- Installed-browser Mandarin TTS is a demo fallback, not approved curriculum audio.
- Speaking UI does not record or score speech.
- Handwriting canvas does not judge correctness or stroke order.
- Review intervals are simplified 1/3/7-day UI examples.
- QR, native XLSX parsing, real virtual classes, messaging delivery and payments remain representations/integrations for the next stage. CSV import is interactive but only changes sample data in memory.
- Charts and most learning dimension percentages are explicitly labeled illustrative.
- Parent/student ownership and permission guards must be enforced again in authenticated server/database code.
