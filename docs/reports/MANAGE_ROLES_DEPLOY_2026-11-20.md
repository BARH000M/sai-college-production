# manage-roles deployment — 2026-11-20

## Why

The Super Admin dashboard failed with:

```
تعذر تحميل مؤشرات النظام: manage-roles (HTTP 400): رفض الخادم الطلب؛ تحقق من البيانات والصلاحيات.
```

The handler returns `400` only for an unreadable body, a missing `action`, or an unknown `action`.
The portal sends `{ "action": "summary" }`, which the current source supports, so the hosted
function was older than the source that calls it — consistent with
`docs/reports/BUILD_AND_DEPLOYMENT_REPORT.md`, which recorded `manage-roles` **v9 (legacy, verify_jwt=false)**
as still active.

## What was deployed

- Slug: `manage-roles`
- Source: the reviewed local handler (`supabase/functions/_shared/role-management-handler.ts` +
  `_shared/mutation-gate.ts`), inlined into `supabase/functions/manage-roles/index.ts` so the
  deployed artifact has no cross-directory imports it cannot resolve.
- `verify_jwt` is now **true** (the gateway verifies the caller token; the handler still performs its own
  super-admin and confirmation checks). This is stricter than the previous `false` and is intentional.
- No SQL, RLS policy, migration or data change was made in this step.

3. Re-open the Super Admin dashboard and press **تحديث المؤشرات**; the error banner should disappear.
