# Yemen SAI — تنفيذ الربط المشترك (10 نوفمبر 2026)

## ما تم تجهيزه في هذه الحزمة

- صفحة إعدادات حقيقية في React (16 مجموعة إعدادات، مفاتيح مسموحة فقط) + شاشة Flutter تقرأ/تعدل الجدول نفسه.
- جدول `public.sai_system_settings` مع RLS: المدير العام فقط يغير الإعدادات المركزية؛ المدير يقرأ الإعدادات غير الحساسة دون تعديل، وباقي المستخدمين لا يصلون. سجلات التدقيق `sai_system_settings_audit` يقرأها المدير العام فقط. لا تُمنح للعملاء صلاحية حذف الإعدادات أو تحرير سجل التدقيق.
- صفحات الويب لمركز التحميل، المخزون، النقل، ملفات الإنجاز، السكن، الشهادات، Front CMS، والخريجين؛ تستخدم جداول حزمة Flutter v1.2 بالاسم نفسه. عمليات الإضافة/التعديل محدودة بدور المستخدم وسياسات RLS. حُذفت سياسات الحذف للسجلات الحساسة (الشهادات والخريجون وملفات الإنجاز والمخزون والغرف)، ولا يُسمح بحذفها مباشرة عبر أي عميل بعد تطبيق 032.
- صفحة موقع عامة `/pages` وقائمة محتوى `/pages/{branchId}/{slug}` تعرض المنشور من `sai_cms_pages` فقط، وتعرض النص آمناً دون تفسير HTML خام.
- تفعيل قراءة وتحرير إعدادات الهاتف من Supabase بدلاً من قائمة بلا وظيفة.
- تحديث القائمة الجانبية والروابط وFooter في واجهة الموقع.
- **لم تُنشأ قواعد بيانات أو حسابات منفصلة.** المشروع الوحيد `aeryusbrulqdxjdynwfh`.

## ما لم يُنفذ ولماذا

**تغيّرت قاعدة البيانات الرئيسية بالفعل** عبر Supabase: أُنشئت جداول الإعدادات والوحدات الثمانية مع RLS وسجلات التدقيق وتفعيل Realtime للجداول الجديدة. اقرأ `LIVE_DATABASE_STATUS_2026-11-10.md`؛ **لا تعاود تطبيق ملفات SQL القديمة**. **GitHub لم يتغيّر**: استدعاء إنشاء فرع عبر الاتصال رجع HTTP 403 `Resource not accessible by integration`. تم تجهيز الملفات لتطبيقها داخل VS Code محلياً؛ لا تدّعي الحزمة نشرها في الموقع أو المتجر.

المجموعة الخاصة بالرسائل القصيرة/واتساب/البريد تحفظ الإعدادات الوصفية فقط؛ إرسال الرسائل يتطلب مزوداً معتمداً وEdge Functions وأسراراً محفوظة في Supabase Secrets. كذلك الحقول المخصصة، تحديث التطبيق الفعلي، إنشاء النسخ الاحتياطية، حظر IP في WAF، تحصيل المدفوعات، إصدار شهادة موقعة رقمياً، وتخزين الملفات الفعلي **ليست خدمات مكتملة في هذه الحزمة**. لا تضع مفاتيح سرية في `sai_system_settings` أو ملفات Flutter/React.

## قبل التطبيق (مرة واحدة)

1. تأكد أن فرع Git لديك نظيف وأن `main` محدث. **لا تستعمل force push أو reset hard**.
2. احفظ نسخة موثوقة من DB عبر Supabase Backup أو `pg_dump` مع أسرار محفوظة على جهازك، وتأكد أن الاستعادة قابلة للتنفيذ على قاعدة اختبار معزولة.
3. تأكد من سجل الترحيلات الفعلي على المشروع قبل أي تغيير جديد؛ هناك انجراف في أسماء/تواريخ الترحيلات مقارنة بملفات GitHub، فلا تفترض أن المراحل 001–028 كلها موجودة.
4. الجداول المطلوبة موجودة في main بالفعل؛ **لا تنفذ ملفات SQL الموجودة بهذه الحزمة على main**. جهّز staging واختبر أدوار المستخدمين التسعة على المخطط الحي المنسوخ بطريقة آمنة.
5. لا تطبق أي ترحيلات إضافية قبل النسخ الاحتياطية واختبارات staging. يجب مزامنة سجل ترحيلات الإنتاج الفعلي مع المستودع بطريقة مراجَعة، لا بإعادة تنفيذ المسودات.

إذا كنت قد ركبت حزمة `Yemen_SAI_Mobile_v1_2_Update.zip` على `D:\SAI-College-Production\mobile` بالفعل:

```powershell

powershell -ExecutionPolicy Bypass -File '.\scripts\APPLY_TO_REPO.ps1' -Repo 'D:\SAI-College-Production'
```

إذا كان مجلد mobile لا يزال إصداراً سابقاً، طبّق حزمة الهاتف v1.2 أولاً مع الحفاظ على التعديلات المحلية، **أو** شغّل سكربت التكامل مع `-SkipMobile` لتعديل موقع الويب فقط. السكربت يرفض العمل عند وجود تغييرات Git غير محفوظة، ويجهز نسخة من ملفات الويب المعدلة خارج مجلد المشروع.

**ملاحظة:** Flutter يتطلب Android toolchain وSupabase publishable key، ولا يُستخدم `service_role` في أي عميل. التحقق البرمجي في هذه الحزمة لا يعوض بناء APK أو اختبارات قاعدة البيانات الفعلية.

## معايير قبول نهائية

- لا يرى الطالب/ولي الأمر إعدادات الإدارة ولا سجلات الغير.
- لا يمكن للعميل إسناد دور أو إدخال دفعة مالية مباشرة أو حذف سجل تدقيق؛ سجلات الوحدات الجديدة تمتلك بصمة الخادم وسجل تغيير.
- كل تغيير غير سري ينفذه المدير العام في إعدادات الإدارة يقرأه الويب والهاتف من الجدول نفسه.
- الموارد والأصناف والنقل وملفات الإنجاز والسكن والشهادات وصفحات CMS والخريجون في الويب والهاتف تُقرأ من الجداول الموجودة في migration 029، ولا تُخزن محلياً كبيانات تجريبية في وضع Live.
- Front CMS يُظهر المنشور فقط لزوار الموقع؛ لا يُظهر المسودات.
- بيانات الفروع والطلاب متوافقة؛ لا يُسمح بمطابقة طالب مع سجل في فرع مختلف.
- أي خدمة خارجية تحتاج أسراراً لا توهم المستخدم بأن كتابة إعداد في الجدول تعني تشغيلها.
