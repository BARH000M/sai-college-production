# قائمة تجهيز Yemen SAI للنشر — Google Play وApp Store

هذه القائمة تفرق بين ما أصبح موجوداً في حزمة التحديث وما يتطلب حسابات أو قرارات من مالك التطبيق. نجاح تثبيت التطبيق لا يعني أن المتجر وافق عليه.

## ما تم تجهيزه في التطبيق

- الاسم الظاهر: **Yemen SAI**، وهوية الكلية الحمراء والذهبية.
- بدأ تطبيق Android يستهدف API 36 في `SETUP.ps1`، وتتحقق منه خطوة بناء AAB.
- إنشاء حزمة Google Play بصيغة AAB عبر `BUILD_PLAY_RELEASE.ps1` بعد إعداد توقيع الإصدار.
- اتصال Supabase يستخدم مفتاحاً عاماً فقط. يمنع سكربت البناء مفاتيح `service_role` و`sb_secret`.
- أضيفت صفحة تدريب للمفردات الصينية المنشورة: نطق صيني عبر محرك الجهاز، معنى عربي، مثال، اختيار من متعدد، مساحة كتابة على الشاشة، وتسجيل تقدم الطالب.
- أضيفت صورتان تعليميتان لـ **门 mén — باب** و**猪 zhū — خنزير**. النص الصيني يرسمه التطبيق بخط صيني ولا يُخبز داخل الصورة.
- أضيفت قراءة سجلات الحضور واستحقاقات الرسوم حسب سياسات RLS. لا تنفذ شاشة التطبيق تسجيل دفعات مالية مباشرة.
- تبقى الاختبارات والجدول الدراسي معلّقين حتى اعتماد وإضافة مخطط قاعدة البيانات لهاتين الوحدتين؛ لا توجد جداول لهما الآن.

## إعداد Android قبل الإصدار

1. شغّل `SETUP.ps1` ثم جهّز ملف `android/key.properties` خارج Git، واربطه بكتلة `signingConfigs.release` في ملف Gradle. لا ترسل ملف المفتاح أو كلمة مروره في المحادثة.
2. تحقق من حفظ نسخة احتياطية آمنة من مفتاح التوقيع. فقدانه قد يمنع تحديث التطبيق المنشور.
3. من PowerShell داخل مجلد `mobile` شغّل `BUILD_PLAY_RELEASE.ps1`. يوقف البناء عند فشل التحليل أو الاختبارات أو غياب إعدادات التوقيع وAPI 36.
4. في Play Console أكمل بيانات الناشر، تصنيف المحتوى والعمر، رابط الخصوصية، نموذج Data safety، تعليمات حذف الحساب/البيانات عند انطباقها، بيانات الدعم، الصور ولقطات الشاشة، بيانات الوصول للمراجعين، واختبار المسار الداخلي قبل النشر العام.
5. عاين سلوك TTS على أجهزة Android مختلفة؛ النطق يعتمد على محرك وأصوات الجهاز وقد يتطلب تنزيل بيانات صوتية.

## إعداد iOS قبل App Store Connect

- يلزم جهاز macOS مع Xcode وحساب Apple Developer لإعداد Bundle ID والتوقيع والشهادات وملف provisioning، ثم أرشفة التطبيق ورفعه عبر Xcode أو Transporter.
- راجع الحد الأدنى لإصدار iOS ومتطلبات SDK الحالية في Xcode وقت الرفع؛ أنشئ صفحة خصوصية عامة، وأكمل ملصق الخصوصية، تصنيف العمر، معلومات الدعم، لقطات كل أحجام الأجهزة وبيانات حساب المراجعة.
- إذا كان التطبيق يسمح بإنشاء الحساب من داخله، وفّر مساراً داخل التطبيق لطلب حذف الحساب والبيانات، مع تنفيذ آمن على الخادم وتوضيح فترة الاحتفاظ القانونية. حذف جلسة الدخول محلياً لا يحذف الحساب.
- لا يمكن تجهيز توقيع Apple أو رفع التطبيق من Windows أو من هذه الحزمة وحدها.

## الخصوصية والبيانات التي يلزم الإفصاح عنها

افحص التطبيق وسياسة الخصوصية الفعلية قبل ملء النماذج. قد يتعامل التطبيق بحسب الدور والاستخدام مع الاسم والبريد والهاتف والملف الأكاديمي والحضور والواجبات والتقدم التعليمي والرسوم وسجلات استخدام الخدمة. حدّث سياسة الموقع لتغطي تطبيق الهاتف، Supabase، مدة الاحتفاظ، طلب الوصول والتصحيح والحذف، بيانات القاصرين وموافقة ولي الأمر، ووسائل التواصل. صفحة السياسة الحالية على الموقع يجب مراجعتها وتحديثها قبل النشر: https://www.sai-academic.com/privacy-policy .

## أمن Supabase — نتيجة فحص هذه المراجعة

- تفعيل RLS موجود للجداول التي تمت مراجعتها، وتقدم المفردات يتيح الكتابة فقط إذا طابق الطالب المستخدم المصادق عليه.
- أظهر Security Advisor: دالتان دون `search_path` مثبت لـ `sai_library_issue` و`sai_library_return`؛ ثلاث دوال تقديم/استعلام قبول متاحة لدور `anon`؛ وتحذيرات لدوال `SECURITY DEFINER` للمستخدمين المصادق عليهم. يجب تدقيق جسم كل دالة وصلاحياتها واختبارات إساءة الاستخدام قبل تغيير المنح. لم تُجرَ تغييرات DDL على قاعدة الإنتاج ضمن هذا التحديث.
- ميزة حماية كلمات المرور المكشوفة معطّلة حالياً. فعّلها من Supabase Dashboard: **Authentication → Settings → Password security → Leaked password protection** ثم أعد فحص Security Advisor.
- لا تضع مفتاح `service_role` أو `sb_secret` في التطبيق أو Git أو متجر التطبيقات؛ استخدم مفتاح anon القديم أو `sb_publishable` فقط مع RLS.
- لم يتوفر ماسح فيروسات/اعتماديات في بيئة إعداد الحزمة، لذلك لا يصح وصف التطبيق بأنه خالٍ من الفيروسات. شغّل ماسح ملفات وSCA على جهاز الإصدار وعلى ملف AAB قبل النشر، وراجع صلاحيات Android/iOS والاعتمادات.

## جاهزية الإطلاق الفعلية

الحزمة **مجهزة للبناء والتحقق محلياً**، وليست موافقة نشر تلقائية. لا تزال بحاجة إلى: إعادة تشغيل Flutter analyze/test/build على جهازك؛ توقيع Android وApple؛ تحديث سياسة الخصوصية وبيانات الحذف؛ تعبئة إفصاحات المتجر بدقة؛ تدقيق تحذيرات Supabase؛ استكمال مخططي الاختبارات والجدول؛ وتجربة تسجيل الدخول والأدوار والبيانات على حسابات اختبار حقيقية.
