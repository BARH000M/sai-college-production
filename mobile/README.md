# تطبيق كلية ساي للجوال

تطبيق Flutter عربي RTL للكلية، مستقل عن تطبيق YSMS المؤرشف. يقرأ الهوية من `public.profiles` والأدوار من `public.user_roles`، ولا ينشئ أدوارًا أو حسابات من التطبيق.

## ما يعمل في هذه المرحلة

- تسجيل الدخول بالبريد وكلمة المرور عبر Supabase Auth، واستعادة كلمة المرور.
- تحميل ملف المستخدم والأدوار المسندة إليه بعد المصادقة.
- واجهة عربية RTL بخط Cairo وشعار كلية ساي وألوان التصميم المعتمد.
- قائمة وحدات تُرشّح حسب الأدوار التسعة الموجودة في مخطط الكلية.
- تبديل الدور النشط عند وجود أكثر من دور مسند فقط.
- سجل الطالب للطالب نفسه، وسجلات الأبناء المرتبطين والمؤكدين لولي الأمر.
- شاشة حساب وتسجيل خروج، وحالات خطأ واضحة عند غياب الملف أو الدور أو الاتصال.

واجهات بقية الوحدات والجدول والتنبيهات هي نقاط ربط أولية؛ لا تعرض سجلات وهمية ولا تدّعي اكتمال عمليات الجوال. تُنفّذ شاشات كل وحدة بعد مطابقة استعلاماتها مع جداول وسياسات RLS وخدمات الويب الحالية.

## تشغيل التطوير على Windows

يستخدم التطبيق مشروع Supabase الرئيسي بناءً على اختيارك، والمفتاح العام (publishable key) فقط. لا تضع `service_role` أو كلمة مرور قاعدة البيانات في التطبيق.

```powershell
Set-Location 'D:\SAI-College-Production\mobile'
flutter pub get
flutter run `
  --dart-define=SUPABASE_URL=https://aeryusbrulqdxjdynwfh.supabase.co `
  --dart-define=SUPABASE_PUBLISHABLE_KEY=PASTE_PUBLIC_KEY_HERE
```

استبدل `PASTE_PUBLIC_KEY_HERE` بالمفتاح العام من إعدادات مشروع **sai-college-production / main**. المفتاح قيمة عامة للتطبيق؛ لا ترسل المفاتيح أو كلمات المرور في المحادثة.

اسم المتغير القديم `SUPABASE_ANON_KEY` ما زال مقروءًا كمفتاح احتياطي، لذلك سكربتات البناء الحالية تعمل دون تعديل.

لإنشاء APK تجريبي:

```powershell
flutter build apk --debug `
  --dart-define=SUPABASE_URL=https://aeryusbrulqdxjdynwfh.supabase.co `
  --dart-define=SUPABASE_PUBLISHABLE_KEY=PASTE_PUBLIC_KEY_HERE
```

## الجودة والتحقق المستمر

سير عمل `Mobile CI` في `.github/workflows/mobile-ci.yml` يعمل عند كل دفعة أو طلب دمج يمس مجلد `mobile`، وينفّذ:

```powershell
flutter pub get
flutter analyze --fatal-infos --fatal-warnings
flutter test
```

`--fatal-infos` مقصود: تحذيرات الإهلاك (deprecations) تُصنَّف معلومات، وبهذا الخيار تفشل البناء فور استخدام واجهة مهجورة قبل أن تتراكم.

## الشاشات ونظام التصميم

كل الشاشات تستخدم حزمة `lib/design_system`:

- `SaiPageScaffold` و`SaiPageBody` للصفحات والهوامش.
- `SaiSectionTitle` و`SaiCard` و`SaiListTile` و`SaiMetricCard` للعناوين والبطاقات والقوائم والأرقام.
- `SaiAsyncState` و`SaiLoadingState` و`SaiErrorState` و`SaiEmptyState` لحالات التحميل والخطأ والفراغ.

لا تُكتب بطاقات أو مؤشرات تحميل محلية جديدة؛ أضف ما تحتاجه إلى نظام التصميم أولًا ليبقى الشكل موحدًا.

## إعدادات الدخول

أضف عنوان إعادة التوجيه التالي إلى قائمة Supabase Auth المسموحة عند استخدام استعادة كلمة المرور:

```text
saicollege://auth/callback
```

معرّف Android وiOS الحالي هو `com.saicollege.mobile`؛ ثبّته قبل أول نشر على المتجر.

## ترتيب الربط التالي

1. الطالب وولي الأمر: ملفات الطلاب المرتبطة، الجدول، الحضور والواجبات.
2. المعلم: الصفوف المسندة، الحضور والتقييم.
3. الإدارة والاستقبال: القبول والطلاب والجداول.
4. المحاسب: الرسوم والإيصالات عبر عمليات الخادم المعتمدة فقط.
5. أمين المكتبة ومحرر المحتوى: الإعارة، التأليف، المراجعة والنشر.

كل دور ظاهر في الهاتف هو لتسهيل التنقل فقط؛ سياسات RLS والتحقق من الخادم تبقى حد الصلاحية الفعلي.
